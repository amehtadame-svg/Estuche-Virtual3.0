# Auditoría de requisitos funcionales

**Base:** rama `feature/verificacion-modulo-empleados`, integración con `main` en `72ec50b`; revisión de código realizada el 26-11-2026. Los 30 RF se encuentran en `docs/requisitos/RFs/`. Las 40 historias HU relacionadas se mantienen en la documentación y no se evaluaron individualmente en esta matriz.

**Criterio:** «implementado en el flujo revisado» significa que hay código para la función principal, no certificación exhaustiva de todas las reglas; «parcial / diferente» indica que falta o cambia al menos una condición documentada; «no encontrado» significa que no se localizó una implementación funcional en las rutas y módulos revisados, no que se haya probado toda posibilidad. Una tabla de base de datos, una pantalla o una prueba aislada no garantizan una función completa. No se consultó ni modificó la base Supabase. La evidencia enlaza archivos de la versión auditada.

## Prioridades sugeridas

1. Corregir el formulario público de Contacto que dice «enviado» sin enviar; y no presentar como verificadas reseñas calculadas. Son hallazgos de información engañosa, no se modificaron en esta tarea sin acordar el comportamiento deseado.
2. Decidir reglas de eliminación de categorías y proveedores antes de usar dichas acciones; actualmente pueden desvincular información.
3. Acordar si los RF antiguos de proveedor, verificación de correo, pagos y exclusividad de roles siguen vigentes o deben actualizarse a las decisiones recientes del proyecto. No implementar cambios en pagos sin una decisión expresa.
4. Definir el alcance deseado para lista de deseos, reseñas, notificaciones, varias direcciones y recuperación de contraseña persistente.
5. Probar recorridos con una base de pruebas dedicada, sin usar datos reales; verificar manualmente la configuración y migraciones antes de desplegar.

## Referencias técnicas visibles en la aplicación

La búsqueda estática de identificadores HU/RF en el código de aplicación encontró una cadena generada para el movimiento de stock inicial (`HU-001`). Se cambió para registros nuevos; la presentación traduce exactamente esa cadena histórica en inventario sin modificar datos existentes. No se alteran las notas escritas por usuarios ni la documentación/pruebas que conservan trazabilidad. Podrían existir otros textos ya almacenados en la base real o imágenes que no se pueden inspeccionar con esta revisión sin conexión.
