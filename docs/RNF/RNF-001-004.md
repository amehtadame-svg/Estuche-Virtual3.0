RNF-001 — Rendimiento

Tipo: Requisito No Funcional de Rendimiento

Descripción

El sistema debe ofrecer un desempeño eficiente, garantizando tiempos de respuesta adecuados y estabilidad durante la operación bajo carga.

Requisitos Específicos

RNF-001.1 — El sistema debe soportar al menos 200 usuarios concurrentes sin presentar degradación perceptible en el rendimiento.

RNF-001.2 — La página principal y el catálogo deben cargar en un tiempo inferior a 3 segundos en el 95% de las solicitudes.

RNF-001.3 — El sistema debe procesar hasta 50 transacciones por minuto sin errores ni pérdida de información.

RNF-001.4 — Durante picos de carga, el uso del procesador del servidor debe mantenerse por debajo del 80%, mediante la optimización de consultas y recursos.

RNF-002 — Seguridad

Tipo: Requisito No Funcional de Seguridad

Descripción

El sistema debe proteger la información de los usuarios y garantizar la confidencialidad, integridad y disponibilidad de los datos durante su transmisión y almacenamiento.

Requisitos Específicos

RNF-002.1 — Toda la comunicación entre el cliente y el servidor debe realizarse mediante el protocolo HTTPS, asegurando el cifrado de extremo a extremo.

RNF-002.2 — Las contraseñas de los usuarios deben almacenarse utilizando algoritmos de hash seguros con sal, como bcrypt o SHA-256.

RNF-002.3 — El sistema debe registrar en un log de auditoría los intentos de acceso, las compras realizadas y las modificaciones críticas efectuadas por los usuarios.

RNF-002.4 — La sesión del usuario debe cerrarse automáticamente después de 15 minutos de inactividad.

RNF-003 — Fiabilidad y Disponibilidad

Tipo: Requisito No Funcional de Fiabilidad y Disponibilidad

Descripción

El sistema debe garantizar la continuidad del servicio y la recuperación de la información ante fallos o incidentes.

Requisitos Específicos

RNF-003.1 — El sistema debe mantener una disponibilidad mínima mensual del 99.5%.

RNF-003.2 — La base de datos debe contar con copias de seguridad automáticas diarias.

RNF-003.3 — Ante fallos imprevistos, el servicio debe recuperarse automáticamente en un tiempo inferior a 5 minutos.

RNF-004 — Mantenibilidad y Portabilidad

Tipo: Requisito No Funcional de Mantenibilidad y Portabilidad

Descripción

El sistema debe facilitar su mantenimiento, evolución y ejecución en diferentes plataformas y entornos.

Requisitos Específicos

RNF-004.1 — El proyecto debe mantener una cobertura de pruebas unitarias superior al 70%.

RNF-004.2 — El código fuente debe desarrollarse de forma modular y documentarse siguiendo los estándares definidos por el proyecto.

RNF-004.3 — La aplicación debe ser compatible con los sistemas operativos Windows y Linux.

RNF-004.4 — El sistema debe funcionar correctamente en los principales navegadores web: Google Chrome, Mozilla Firefox, Microsoft Edge y Safari.
